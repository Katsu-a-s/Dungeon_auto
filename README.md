# Dungeon Auto

Python + [pygame](https://www.pyga.me/) 製のローグライク風ダンジョン探索ゲーム。
メインファイルは **`dungeon_rev174.py`**(単一ファイル構成、約8,500行)。

> このリポジトリは Claude によるルーティン作業(1時間ごとの自動開発)で
> 少しずつ機能追加・改善が行われています。このREADMEも実装状況に合わせて
> 逐次更新されます。

## このゲームってどんなゲーム?(はじめての人向け)

`Dungeon Auto` は、迷路になった地下ダンジョンを歩き回って、モンスターと戦い
ながら深い階を目指す1人用のRPGです。難しい前提知識はいらず、次のことを
繰り返すだけで遊べます。

1. 矢印キーでダンジョンの中を歩いて探索する(壁にぶつからないように迷路を進む)。
2. モンスターに出会ったらバトル開始。攻撃・ポーション(回復)・爆炎石(強力な
   一撃)・防御・逃走などのコマンドから選んで戦う。
3. 階段を見つけたら次の階へ。10階ごとに強いボスが待っている。
4. レベルアップしてスキルを覚えたり、宝箱からアイテムを手に入れたりしながら、
   全3ステージ×30階(合計90階)のクリアを目指す。全クリア後は、育てたキャラの
   ままさらに奥まで潜り続けられる「エンドレス・ディープス」にも挑戦できる。

ゲームオーバーになってもレベルや装備は引き継がれないシンプルなローグライク
寄りのルールですが、実績(称号)やコレクション要素(図鑑)がたくさんあるので、
1回のプレイが短くても「もう1回だけ」とやり込みたくなるように作られています。
操作に迷ったら、タイトル画面右上の `[F1] Help` からいつでも操作方法を確認できます。

## 遊び方

```bash
pip install pygame
python3 dungeon_rev174.py
```

- 画面サイズ 880x720、キーボード + マウス操作対応。
- セーブデータ等(`savefile*.json` / `autosave.json` / `settings.json` など)は
  実行時にリポジトリ直下へ自動生成されます(`.gitignore` 済みでコミット対象外)。

## 操作方法

ゲーム内タイトル画面右上の **`[F1] Help`** ボタン(または `F1` キー)から、
いつでもコントロール一覧を確認できます。

| 場面 | キー | 内容 |
|---|---|---|
| タイトル | 矢印キー / `Space` | メニュー選択 / ゲーム開始 |
| タイトル | `T` | 難易度切り替え(Easy/Normal/Hard/Nightmare※/Abyss※※) |
| タイトル | `N` | キャラクター選択 |
| タイトル | `G` | ゲームデータ(ロード/コンティニュー/設定) |
| タイトル | `R` | 記録(実績/統計/図鑑/エコーバトル/デイリーランキング) |
| タイトル | `Y` | デイリーチャレンジ開始 |
| タイトル | `H` | 隠しステージ(全クリア後に出現) |
| タイトル | `F1` | ヘルプ画面 |
| ダンジョン探索 | 矢印キー | 移動 |
| ダンジョン探索 | `Q` | セーブメニュー |
| ダンジョン探索 | `K` | スキルツリー |
| ダンジョン探索 | `P` | ペット情報(仲間がいる時のみ) |
| ダンジョン探索 | `I` | ポーション使用 |
| バトル | `A`/`P`/`B`/`R`/`D`/`F`/`U`/`C` | 攻撃/ポーション/爆炎石/逃走/防御/集中/必殺技(コンボ5必要)/反撃 |
| バトル | `Up`/`Down`, `Space`/`Enter` | コマンド選択/決定 |
| 共通 | `Esc` | 戻る・キャンセル |
| 共通 | `M` | 全音声(BGM/SE)をミュート/解除 |

※ Nightmare難易度は、Hardクリア実績(hard_clear)を解除するまでは
`T`キーでの切り替えサイクルに出てきません。まずHardで全ステージクリアして
アンロックしてください。

※※ Abyss難易度は、さらにその上の最上位難易度です。Nightmareクリア実績
(nightmare_clear)を解除するまでは選べません。しかも他の難易度と違い、
**このモードで力尽きるとオートセーブそのものが消え、続きからやり直せません**
(手動セーブも使えません)。まさに一発勝負を求める玄人向けの挑戦です。

※※※ 全3ステージをクリアすると出る「GAME CLEAR!」画面で `[X]` キーを押すと、
そのままのレベル・スキル・所持品で91階以降の「エンドレス・ディープス」に
突入できます(`[Space]`キーならこれまで通りタイトルに戻ります)。

## 現在の実装状況

### ダンジョン・進行
- 全 **3ステージ × 30階 = 90階**(`STAGE_LENGTH`/`STAGE_COUNT`)+ 全クリア後の隠しステージ(ボス戦)。
- **新ゲームモード「エンドレス・ディープス」**:全3ステージをクリアした
  「GAME CLEAR!」画面で `[X]` キーを押すと、その時点のレベル・スキル・
  所持品を引き継いだまま、91階以降どこまでも続くダンジョンに挑戦できる。
  これまでは全クリアするとそこで冒険が終わり、やり込んだキャラクターの
  その先の力試しができる場所が無かったため、既存3ステージ+隠しステージとは
  別の「終わりの無いエリア」として新設した。ボスは相変わらず10階ごとに
  登場し、フロアを進むほど`emy_lifemax`/`emy_str`が伸びる既存の計算式が
  そのまま際限なく効くため強さも青天井。30階進むごとに既存の「拠点
  (サンクチュア)」で一息つける仕組みも共通で使える。今どこまで潜れたかは
  探索中のHUDに常時表示され、通算の自己ベスト(記録画面のプレイ統計にも
  表示)を更新するたびにフロア100・150到達でそれぞれ新実績
  「Endless Delver」「Endless Legend」が解除される。
- 迷路生成 + フロア修飾(霧/豊穣/岩場/煌めき/静穏/幸運/共鳴/氷結/剛力/豊穣の森/静謐/呪い/静寂/快晴/精鋭の巣/豪奢/光輝/慈悲/護り/市場/実直/肥沃/揮発/灯火/平穏/要塞/弱体(HP)/群棲/脆弱(ATK)/不毛/頑健/もつれ/危険/破滅/質素/湿潤/曇天/凶運/不作/割高/鈍色/腐食/鈍重/希薄/鈍化(コンボ)/無毒/狂奔/猛毒/集中/吸血/聖域/木霊/過負荷/背信/瘴気/浄化/堅牢など、
  `FLOOR_MODIFIERS`、計62種類)。
- **新フロア特性「Bulwark Floor(堅牢の床)」**:このフロアでは、新しい
  バトルコマンド「反撃(Counter)」の被ダメージ軽減量・反撃ダメージが
  ともに1.5倍になる。特定のバトルコマンド専用に効果を伸ばすフロア特性は
  Focused Floor(Focusの威力を強化)・Overcharged Floor(Ultimateの解放
  条件を緩和)に続いて3つ目で、今回追加したCounterコマンドにも同じ
  「そのコマンドが得意になるフロア」を用意した。
- **新フロア特性「Festering Floor(瘴気の床)」「Cleansing Floor(浄化の床)」**:
  このフロアでは、毒の減りが50%遅く(Festering)/50%速く
  (Cleansing)なる。既存の毒関連特性(Toxic/Venomous/Antiseptic/Serene)は
  すべて毒の「発生確率」を上下させるだけで、一度かかった毒が「どれくらい
  長引くか」という持続時間側に関わる特性が無かったため、新しい方向性
  として2つ同時に追加した。呼び出し側で毒の減少量が最低1になるよう
  下限を設けており、Festering Floor+低難易度の組み合わせでも毒が
  永久に抜けなくなる事故は起きない。
- **新フロア特性「Treacherous Floor(背信の床)」**:このフロアでは、
  宝箱がミミック(化けている宝箱)である確率が通常の2倍(12%→24%)になる。
  既存のGenuine Floor(ミミックが一切混ざらなくなる「当たり」特性)は
  安全にする方向のみの特性だったため、Frail⇔Hardenedなどと同じ「既存修飾子の
  符号を反転させる」パターンで、`modifier_mimic_chance_mult()`という新しい
  関数を追加し対になる「はずれ」特性を安全に追加した(呼び出し側の判定
  `random.randint(0, 99) < min(99, ...)`で100%を超えないようクランプ済み)。
- **新フロア特性「Overcharged Floor(過負荷の床)」**:このフロアでは、
  バトルコマンド「必殺技(Ultimate)」の発動に必要なコンボ数が、通常の5から
  3に下がる。これまでのフロア特性はダメージ・確率・移動速度などの数値を
  上下させるだけで、バトルコマンドそのものの「解放条件」を変える特性が
  無かったため、`modifier_ultimate_combo_requirement()`という新しい方向の
  関数を追加した。コンボを3まで積めば以降は毎ターンでもUltimateを連発
  しやすくなる、テンポ重視の「当たり」特性。
- **新フロア特性「Echoing Floor(木霊の床)」**:このフロアでは、
  通常攻撃(Attack)が命中するたびに25%の確率で、半分の威力の追加攻撃が
  即座にもう1回入る。これまでのフロア特性はどれも1回の攻撃の威力・回復量・
  確率などの「数値」を上下させるだけだったが、これは「攻撃という行動
  そのものがもう1回起こるかもしれない」という、今までに無かった発動
  タイミングの特性(`modifier_echo_chance()`を新設)。運が良ければ1回の
  コマンドで2発分のダメージが飛び出す、駆け引きよりも爽快感を狙った
  「当たり」特性。
- **新フロア特性「Sanctuary Floor(聖域の床)」**:このフロアでは、
  敵を倒した瞬間にHPが全回復する。既存のVampiric Floor(攻撃がヒットする
  たびに少しずつ回復する「オンヒット型」)とは違い、「敵を倒しきった瞬間に
  まとめて回復する」という発動タイミングそのものが新しい「オンキル型」の
  特性として`modifier_full_heal_on_kill()`を追加した。ギリギリのHPで
  トドメを刺せるかどうかの駆け引きに、大きな安心感というご褒美を加えている。
- **新フロア特性「Vampiric Floor(吸血の床)」**:このフロアでは、
  通常攻撃(Attack)がヒットするたびに、与えたダメージの15%が自分のHPとして
  戻ってくる。従来の特性はダメージ・確率・移動速度などの数値を上下させる
  ものばかりで、「攻撃した結果プレイヤー自身が回復する」という方向の
  仕掛けが無かったため、既存修飾子の符号反転ではない新しいカテゴリの
  特性として`modifier_lifesteal_pct()`を追加した。回復量はダメージポップ
  アップと同じ仕組みで緑色の「+◯」として画面にも表示され、じわじわ削り
  合う長期戦を得意な立ち回りに変えてくれる。
- **新フロア特性「Focused Floor(集中の床)」**:このフロアでは、
  バトルコマンド「集中(Focus)」で強化した次の一撃の威力が、通常のx1.5倍
  からx2.0倍に上がる。クリティカルヒットの威力を伸ばすRadiant Floorや
  コンボ倍率の伸びを速めるResonant Floorはすでにあったが、「集中」自体の
  一撃倍率を伸ばす特性が無かったため、`modifier_focus_mult()`という新しい
  関数を追加して穴を埋めた(既存修飾子の符号反転ではなく、今まで無かった
  方向に新しく倍率を伸ばす特性)。40回集中を使うと解除される既存実績
  「Tactician」とあわせて、集中コマンドを使う理由がさらに増える。
- **新フロア特性「Frenzied Floor(狂奔の床)」**:このフロアでは、
  DEFが-3になる代わりに移動速度が1.15倍(+15%)になる。既存のRocky Floor
  (DEF+3、移動速度-15%)は守り寄りの方向のみだったため、Frail⇔Hardenedなど
  と同じ「既存修飾子の符号を反転させる」パターンで、`modifier_def_bonus()`と
  `modifier_rocky_speed_mult()`にそれぞれ分岐を1つ足すだけで、DEF↔速度の
  トレードオフを攻め寄りにも体験できる対になる特性を追加した。
- **新フロア特性「Venomous Floor(猛毒の床)」**:このフロアでは、
  毒を持つ敵(スライム系など)の攻撃が必ず毒を付与するようになる。毒を
  完全無効化する既存のSerene Floorが「毒を出させない」方向のみの特性
  だったため、その逆に「毒を持つ敵と戦うなら確実に刺さる」ハイリスクな
  対になる特性が無かった穴を埋めた。`modifier_poison_chance_bonus()`に、
  呼び出し側の`30 + 戻り値`が必ず99を超える値(70)を返す分岐を1つ足す
  だけで実装した(toxic/antisepticのような発生率の微調整ではなく、確定
  発生という新しい方向性)。
- **新フロア特性「Sluggish Floor(鈍重の床)」**:このフロアでは、
  移動速度が0.7倍(-30%)になる。既存のWindy Floor(移動速度+30%)は
  移動を速める方向のみの特性だったため、Empowered⇔Weakenedと同じ
  「既存修飾子の符号を反転させる」パターンで、`modifier_speed_mult()`に
  0.7倍の分岐を1つ足すだけで対になる「はずれ」特性を安全に追加した。
- **新フロア特性「Scarce Floor(希薄の床)」**:このフロアでは、
  アイテム発見率が-20%pt下がる。既存のBountiful Floor(アイテム発見率
  +20%pt)は発見率を伸ばす方向のみだったため(Cursed Floorは
  攻撃力とセットになった別方向の特性で対にはならない)、Fortunate⇔Unlucky
  と同じ「既存修飾子の符号を反転させる」パターンで、`modifier_item_bonus()`
  に-20の分岐を1つ足すだけで対になる「はずれ」特性を追加した(呼び出し側の
  宝箱の中身抽選が`max(0, min(99, ...))`でクランプ済みであることを確認して
  から実装したため、マイナス値になってもレアな中身が出にくくなるだけで
  安全)。
- **新フロア特性「Muffled Floor(鈍化の床)」**:このフロアでは、
  コンボ倍率の伸びが1スタックあたり+5%に鈍る(通常+10%の半分)。既存の
  Resonant Floor(+15%)は伸ばす方向のみだったため、同じ符号反転パターンで
  `modifier_combo_bonus_per_stack()`に分岐を1つ足すだけで対になる
  「はずれ」特性を追加した。
- **新フロア特性「Antiseptic Floor(無毒の床)」**:このフロアでは、
  毒の発生確率が-15%pt下がる。既存のToxic Floor(+25%pt)は上げる方向
  のみだったため、Fortunate⇔Unluckyと同じパターンで
  `modifier_poison_chance_bonus()`に分岐を1つ足すだけで対になる
  「当たり」特性を追加した(呼び出し側の`30 + この戻り値`をrandintと
  比較する判定がマイナス値でも安全なことを確認済み)。
- **新実績「Boulder Master」**:通算15回、転がる岩(Rolling Boulder)
  から逃げ切ると解除(称号: the Boulder Master)。初回逃走で解除される
  「boulder_dodge」実績はすでにあったが、Golden Hunter/Rift Master/Bounty
  Masterなどと同様に繰り返し達成し続けることを評価する累積目標が無かった
  ため、既存の記録(`boulders_dodged`)をそのまま活かして追加した。
- **新実績「Altar Devotee」**:通算10回、生贄の祭壇の恩恵(Boon)を
  受け取ると解除(称号: the Favored)。既存の記録(`altar_boons`)を使い、
  Golden Hunter/Rift Master/Bounty Masterと同じ「初回実績はあるが累積実績
  が無かった」パターンの穴を埋めた。
- **【不具合修正】Damp Floor(湿潤の床)がコード上から消失していた不具合を修正
  **:rev154で追加された「Damp Floor」(爆炎石ダメージ-30%)は、
  同時期に並行して作業されていた別のPR(rev155のベース)が、rev154より
  前の`main`を土台にして分岐していたため、その後の3-way mergeで
  README上の記述だけが残り、実際の`FLOOR_MODIFIERS`・
  `modifier_blaze_dmg_mult()`のコードは反映されないまま欠落していた
  (「実行対象は常に番号が最大のファイル」の原則により、この欠落に
  気づかれずrev155→rev156へそのまま引き継がれていた)。あわせて同じ
  経緯で失われていた新実績「Rift Master」(累積10回の裂け目Elite撃破で
  解除)と、記録メニューの図鑑(Bestiary)発見数表示も、rev154時点の
  実装を突き合わせてすべて復元した。
  フロア特性は入室直後だけでなく探索中・バトル中も画面に小さく常時表示され、
  効果を忘れにくいように改善。
- **新フロア特性「Withered Floor(不作の床)」**:このフロアでは、
  拾った食料の回復量が30%減る。既存のFertile Floor(食料回復量+50%)は
  食料を増やす方向のみの特性だったため、Sparkling⇔Drabと同じ「既存修飾子の
  符号を反転させる」パターンで、`modifier_food_yield_mult()`に0.7倍の
  分岐を1つ足すだけで対になる「はずれ」特性を安全に追加した。
- **新フロア特性「Costly Floor(割高の床)」**:このフロアでは、
  旅の商人との取引コストが25%割高になる。既存のBazaar Floor(取引コスト
  -25%)は安くする方向のみの特性だったため、Fortunate⇔Unluckyと同じ
  「既存修飾子の符号を反転させる」パターンで、`modifier_trade_cost_mult()`
  に1.25倍の分岐を1つ足すだけで対になる「はずれ」特性を安全に追加した
  (呼び出し側の`merchant_trade_cost()`が`max(1, ...)`でクランプ済みで
  あることを確認してから実装した)。
- **新フロア特性「Damp Floor(湿潤の床)」**:このフロアでは、爆炎石
  (Blaze Gem)の与えるダメージが30%弱まる。既存のVolatile Floor(爆炎石
  ダメージ+50%)は爆炎石を強める方向のみの特性だったため、Frail⇔Hardened、
  Merciful⇔Ruinousと同じ「既存修飾子の符号を反転させる」パターンで、
  `modifier_blaze_dmg_mult()`に0.7倍の分岐を1つ足すだけで対になる
  「はずれ」特性を安全に追加した。
- **新フロア特性「Drab Floor(曇天の床)」**:このフロアでは、獲得
  EXPが0.8倍(-20%)になる。既存のSparkling Floor(獲得EXP+30%)はEXPを
  伸ばす方向のみの特性だったため、Empowered⇔Weakenedと同じ「既存修飾子の
  符号を反転させる」パターンで、`modifier_exp_mult()`に0.8倍の分岐を1つ
  足すだけで対になる「はずれ」特性を安全に追加した。
- **新フロア特性「Unlucky Floor(凶運の床)」**:このフロアでは、
  クリティカルヒットの発生率が-15%pt下がる。既存のFortunate Floor(+15%pt)
  はクリティカル率を伸ばす方向のみの特性だったため、Tranquil⇔Snaredと同じ
  「既存修飾子の符号を反転させる」パターンで、`modifier_crit_chance_bonus()`
  に-0.15の分岐を1つ足すだけで対になる「はずれ」特性を追加した(呼び出し側が
  `total_crit_chance > 0`を確認してから乱数判定するため、マイナスになっても
  クリティカルが発生しなくなるだけで安全であることを確認済み)。
- **新フロア特性「Meager Floor(質素の床)」**:このフロアでは、宝箱
  (通常の宝箱)の出現重みが半分になる。既存のOpulent Floor(宝箱出現重み

- **新フロア特性「Elite Grounds(精鋭の巣床)」**:このフロアでは通常戦闘が
  エリート化する確率が12%上乗せされる(通常12% → 24%)。エリートは強い代わりに
  経験値ボーナスが付くため、危険を承知でハイリスク・ハイリターンの周回を狙える
  特性として追加した(既存のCursed Floorと同様、リスクとリターンを両方持つ方向性)。

### キャラクター・成長
- 7種の主人公タイプ(Warrior/Guardian/Scholar/Scout/Rogue/Berserker/Prospector)でプレイスタイルを選択可能。
- **新プレイアブルキャラクター「Prospector」**:タイトル画面の
  キャラクター選択(`[N] Hero`)に7人目の主人公を追加。宝箱の中身が良くなる
  「アイテム発見率」が+15%pt上がる代わりに、攻撃力(STR)が-15されるキャラ
  クター。既存6種はアイテム発見率という切り口を誰も持っておらず(この数値は
  難易度・スキル・仲間・フロア特性でしか動かせなかった)、宝探しに全振りする
  「トレジャーハンター」構成として新しい方向性を追加した。必殺技(Ultimate)
  にも専用の「Fortune's Gambit」を用意し、STRを削っている分基礎威力は控えめ
  だが、当たれば他キャラに匹敵する一撃になる「大穴」の振れ幅を持たせた。
  Rogue/Berserkerと同様、新しい立ち絵画像は用意していないため、選択画面では
  顔グラ枠が空欄になる。
- **新プレイアブルキャラクター「Berserker」**:タイトル画面の
  キャラクター選択(`[N] Hero`)に6人目の主人公を追加。攻撃力(STR)が
  +35される代わりに最大HPが-30されるキャラクター。既存5種はDEF・EXP・
  食料・会心率のいずれかを犠牲にする構成だったが、最大HPそのものを
  削って攻撃力に全振りする「ガラスの大砲」構成が無かったため、新しい
  方向性として追加した(初期HP300から-30されても270残るため、序盤から
  即詰みにはならない)。必殺技(Ultimate)にも専用の「Bloodrage」を用意し、
  5人の必殺技の中で最大の威力倍率にすることで、ハイリスク・ハイリターンな
  個性を一撃の重さにも反映させた。Rogueと同様、新しい立ち絵画像は
  用意していないため、選択画面では顔グラ枠が空欄になる。
- **仲間(ペット)システム**:フロア5以降、宝箱の中身がまれに(3%)
  「ペットの卵」に化け、拾った瞬間にランダムな仲間が孵る(1周につき1匹まで)。
  仲間はダンジョン探索中・バトル中ずっとプレイヤーのそばに表示され、常時
  何らかの恩恵をくれる。孵る仲間は次の4種類からランダムで、探索画面と
  バトル画面のステータス欄にはアイコンと一緒に今の仲間の名前+効果が
  常に表示される(画面を切り替えなくても、今の仲間が何をしてくれているか
  一目でわかる)。
  - Slime Pal:バトル中10%の確率で追撃してくれる。
  - Guardian Sprite:常時DEF+3(守りが硬くなる)。
  - Lucky Cat:常時アイテム発見率+5%pt(宝箱の中身が良くなりやすい)。
  - **Ember Whelp**:常時STR+3(攻撃力が上がる)。既存3種は防御・
    運・追撃だけで、素直に攻撃力を底上げしてくれる仲間がいなかったため、
    その穴を埋める新しい仲間として追加した(見た目はSlime Palを炎色に
    染め替えた色違い)。
- **新プレイアブルキャラクター「Rogue」**:タイトル画面の
  キャラクター選択(`[N] Hero`)に5人目の主人公を追加。会心率(クリティカル
  発生率)に+12%ptの上乗せを持つ代わりにDEFが-5される、既存4種には
  無かった「攻撃的な数値に手を出す代わりに守りを削る」ハイリスク・
  ハイリターン構成。新しい立ち絵画像は用意していないため、選択画面では
  他の4人と違い顔グラ枠が空欄になるが、ステータス自体は最初から
  他のキャラクターと同じように使える。
- **新バトルコマンド「Ultimate(必殺技)」+5人分の専用ムーブ**:
  バトル中にコンボを5回つなげると新コマンド`[U]ltimate`が解放され、
  選んだ主人公ごとに全く違う一撃(必殺技)を放てるようになった。Warriorは
  「Rampage」で力任せの大打撃、Guardianは「Guardian's Wrath」で一撃と
  同時にHPも回復、Scholarは「Arcane Overload」でレベルが高いほど威力が
  伸びる知識の力、Scoutは「Piercing Shot」で正確無比な一撃、Rogueは
  「Assassinate」で最大火力の一撃と、5人それぞれの個性がそのまま必殺技の
  演出に表れる。これまでバトルコマンドは全キャラ共通で、キャラクターの
  違いはステータス数値だけに留まっていたが、この必殺技で初めて
  「動き」そのものに個性を持たせた。初使用で実績「Ultimate Unleashed」、
  通算20回使用で「Ultimate Master」が解除される。
- レベル/経験値/所持品(ポーション・爆炎石・食料など)。
- 5系統×3段+奥義1つ、計16スキルのスキルツリー。
- 難易度5段階(Easy/Normal/Hard/Nightmare/Abyss)でパラメータ調整可能。
  Nightmareは玄人向けの上位難易度で、Hardクリア実績(hard_clear)を解除して
  初めてタイトル画面の`[T]`切り替えサイクルに現れる(いきなり選べて初見殺しに
  ならないようにするアンロック制)。歩数ごとの受動回復が完全に0になるのが
  Hardとの一番大きな違いで、ポーションや回復系のフロア特性を計画的に
  頼らないと立ち行かなくなる。プレイ中は画面左上に脈打つ赤文字で
  `*** NIGHTMARE MODE ***`と常時表示され、難易度ボタンの色も
  緑(Easy)→橙(Normal)→赤橙(Hard)→深紅(Nightmare)→紫(Abyss)と危険度に
  応じて変わる。
- **新難易度「Abyss」(パーマデス)**:全難易度の頂点。Nightmareクリア
  実績(nightmare_clear)を解除して初めて選べるようになる。これまでの
  難易度は「数値が厳しくなるだけ」だったが、Abyssは初めて**一発勝負の
  ルール自体を変える**難易度で、力尽きるとその場でオートセーブが消え、
  「[C] Continue」で続きに戻ることができなくなる(セーブメニューでの手動
  セーブも封じられる)。その代わり、Nightmareで削られていた経験値・
  アイテム運はNormal相当まで戻し、敵の強さだけをさらに一段引き上げる
  ことで、「厳しくした分は必ず罰、耐えた分は必ず報酬」という一方的な
  ペナルティ調整に留めない設計にした。クリアすると新実績・新称号
  「the Abysswalker」が解除される。まだNightmareをクリアしていない
  プレイヤーがいきなりAbyssを選ぼうとしても選択肢に出てこないよう、
  難易度切り替え時に「Clear all stages on Nightmare to unlock Abyss
  (permadeath)!」のようなヒントを一時的に表示するようにした。
- **主人公のレベル節目オーラ演出**:Lv10で銅色、Lv20で銀色、Lv30で
  金色の、脈打つ光のオーラがダンジョン探索中の主人公キャラの背後に
  まとわりつくようになる。新しいスプライト画像を用意しなくても、
  golden sprite(金色スライム)で使っている半透明の楕円グロー描画を
  流用するだけで、レベルが上がるほど主人公が見た目にも「強く・かっこよく」
  育っていく感覚を出せるようにした。
- **Lv40「伝説」オーラ+新実績「Legend」**:Lv30の金色オーラが
  これまでの最上位の節目だったため、さらに上を目指したくなるよう
  Lv40に虹色に色が回り続ける特別なオーラを追加した(固定色ではなく、
  時間経過で色相がゆっくり変化し続けるので、金色よりも格上の存在だと
  一目でわかる)。Lv40に到達すると新実績「Legend」(称号: the Legend)も
  解除される。

  ポーションのみ灰色化されており、もう一方の消費アイテムである爆炎石は
  0になっても他の数値と見分けが付かなかったため、表示ルールを揃えて改善した。
- **ポーション/爆炎石の残り僅か事前警告**:画面左下のステータス
  パネルで、ポーション・爆炎石の残り数が1個になった時点で、食料の事前警告
  (残り30以下でオレンジ点滅)と同じ考え方でオレンジ色に点滅するように
  なった。従来は0個になって灰色化するまで数値の見た目に変化が無く、
  「あと1回で尽きる」という状況に気づきにくかったため、0になる前に
  ワンテンポ早く気づけるように改善した。
- **クリティカル/コンボフィニッシャー演出**:クリティカルヒットやコンボ
  フィニッシャーが発動した瞬間、画面全体が短く光るフラッシュ演出を追加し、
  攻撃の爽快感を強化(フィニッシャーはより長く・ピンクがかった色で発光)。
- **ボス階警告**:未撃破のボスがいるフロアに足を踏み入れると、
  「Welcome to floor」表示と一緒に脈打つ赤文字で警告メッセージが表示され、
  階段に着く前にポーションや爆炎石の準備をする猶予が生まれるように。
- **ボス階までの残り階数表示**:ボス階まで残り3階以内になると、
  探索中のHUDに「Boss floor in N」と表示されるように。従来はボス階に
  足を踏み入れた瞬間にしか警告が無く、直前まで準備するタイミングが
  分からなかったため、少し早めに心構えできるように追加した。
- **画面シェイク演出**:被弾時・クリティカルヒット・コンボフィニッシャー発動時に
  画面が数フレームだけ小刻みに揺れるようになり、打撃の重みを強化(ボスの
  フェーズ2/激怒中に被弾すると揺れが一段大きくなる)。
- **ダメージポップアップ**:攻撃がヒットした瞬間、命中した対象(敵/プレイヤー)の
  頭上にダメージ数値がふわっと浮かび上がってフェードアウトするように。固定の
  メッセージ欄だけでは伝わりにくかった「どこで何が起きたか」を視覚的に補強し、
  クリティカルヒットは金色・コンボフィニッシャーはピンク色で一回り大きく強調表示。
- **実績解除トースト**:実績を解除した瞬間、画面上部にバッジ画像付きの
  ゴールドのバナーが上からスライドインして「ACHIEVEMENT UNLOCKED!」と実績名を
  表示するように。従来は他の雑多な通知と同じ地味な1行テキストで、探索中/バトル中
  問わず気づきにくかったが、専用の演出にしたことで達成感がひと目で伝わるように
  なった(探索・バトル・メニューなどどの画面でも表示される)。
- **自己ベストコンボ更新演出**:バトル中に歴代最高コンボ数
  (プレイ統計の「Highest combo streak reached」)を更新した瞬間、
  「New best combo! x◯」というメッセージと共に、クリティカルヒットと同じ
  画面フラッシュ機構を金色で流用して光らせるように。従来は記録自体は
  裏で更新されていても画面上には何の合図も無く、コンボを伸ばす動機づけが
  弱かったため、更新の瞬間にひと目で気づけるように追加した(1バトルにつき
  演出は一度だけに絞り、連続ヒットのたびに出て煩わしくならないようにした)。
- 宝箱から指輪・アミュレットなど希少なアイテム(tier 5〜8)が出た時も、
  ポーションや爆炎石と同じく画面フラッシュ・ジングルの無い、静かな受け取りに
  なる(一時期は専用の金色フラッシュ+ジングルを付けていたが、演出が過剰
  という声を受けてrev172で廃止した)。

### サウンド・アセット
- `image/`:敵・ボス・アイテム・床・エフェクトなど201点のスプライト。
- `sound/`:ステージ別BGM(タイトル/フィールド/バトル、全ステージ分)+ SE + ジングル(レベルアップ/勝利/ゲームオーバー)。
- **実績解除ジングル**:実績解除トーストが表示される瞬間、レベルアップ
  ジングルを再生して音でも達成に気づけるように(従来はゴールドバナーの
  スライドインのみで、BGM/SEに気を取られていると見逃すことがあった)。
- 隠し壁を見つけて壁が開いた瞬間は、既存の攻撃音を発見の合図として
  短く鳴らす(一時期はふつうの宝箱を開けた瞬間にも効果音を鳴らしていたが、
  「合っていない」という声を受けてrev173で廃止し、ポーション・爆炎石等は
  従来通り無音で受け取る)。
- **低HP警告に効果音を追加**:残りHPが最大値の20%を切ると画面端が
  脈打つ赤い縁取りで警告する「Low HP Pulse」演出は、これまで見た目だけの
  演出で音が一切無く、画面の別の場所に気を取られていると気づきにくかった。
  実績解除ジングルと同じ「フラグを立てて次のフレームでmain()側が再生する」
  パターンで、警告状態に入った瞬間だけ既存の攻撃音を短く1回鳴らすように
  した(脈打つたびに毎回鳴らすと煩わしいため、警告に入った最初の一度だけ。
  HPが回復して警告が消えれば、次に再び危険域に入ったときにまた鳴る)。
  設定画面の「Low HP Pulse」トグルをオフにすれば、従来通り視覚・音とも
  演出無しにできる。

## 開発方針

- 既存のコードスタイル・命名規則を踏襲。
- 1回の自動実行あたりの変更は小〜中規模に留め、既存のゲームプレイを壊さない。
- 変更のたびに構文チェック(`py_compile`)・ヘッドレス動作確認
  (`SDL_VIDEODRIVER=dummy` での起動テスト)を実施。
- メインファイルは直接書き換えず、`cp` で複製してから編集する。
  `dungeon_revNNN.py` のNNNを1つ上げた新しいファイル名で保存し
  (例: `dungeon_rev123.py` → `dungeon_rev124.py`)、古いファイルは
  変更履歴としてそのまま残す。**実行・プレイ対象は常に番号が最大の
  ファイル。**バージョンごとの変更履歴をファイル名からも追えるようにする。

## 自動実行環境についてのメモ(つまずいた点)

- **オープンPRが`main`と同じ土台で完成していた場合は、先にマージしてから
  作業を始める**:2026-07-25のある実行時、着手前に`list_pull_requests`を
  確認したところ、別の並行実行が作った「Hardened Floor / Mimic Hunter /
  敵HP数値表示」のPR(#50、`dungeon_rev149.py`)がオープン中で、`main`の
  最新コミットをそのまま土台にしていて動作確認も済んでいた
  (`mergeable_state: clean`)。これを無視して自分も`dungeon_rev148.py`から
  `dungeon_rev149.py`を作ると、ファイル名が競合するだけでなく、マージ順序
  次第でPR #50の3つの変更が「番号が最大のファイルが実行対象」という運用
  ルールのもとで静かに巻き戻ってしまう危険があった。そのため、`rev149`は
  自分では作らず、先にPR #50をマージしてから、マージ後の最新`main`
  (`dungeon_rev149.py`)を土台に`dungeon_rev150.py`を作った。
- **2026-07-25の実行時、`main`の履歴が単一の"update"コミットに書き換えられて
  いた**:このルーティンとは別の操作で`main`のgit履歴が1コミットに整理され、
  それに伴い`dungeon_rev147.py`以前の旧revファイルもすべてリポジトリから
  削除されていた(ローカルクローンの`main`ブランチは書き換え前の古い履歴を
  指したままだったため、`git fetch origin main`を2回実行して強制更新
  (forced update)が来たことで気づけた)。ローカルの担当ブランチが偶然
  書き換え前の`main`と同じコミットを指していて紛らわしかったため、
  `git checkout -B <担当ブランチ> origin/main`で明示的に最新の`origin/main`
  へ揃え直してから作業を始めた。今後も、ローカルの`main`ブランチと
  `origin/main`のコミットIDが一致しているかを都度確認すること。
- **`git fetch origin main` の結果がGitHub上の実際の`main`より古く見える
  ことがある(プロキシ経由のgitキャッシュが原因)**:今回、ローカルの
  git(プロキシ経由)で`origin/main`をfetchすると、直前にマージされた
  はずのPR群が全く反映されていない、何十コミットも古い状態が返ってきた。
  そのまま信じて古い`main`を土台に作業すると、既にマージ済みの内容を
  重複実装したり、最新の`dungeon_revNNN.py`より古いファイルを次のrevの
  ベースにしてしまう危険がある。`main`が想定より古く見えたら、GitHub
  MCPの`get_file_contents`(例: `ref: "refs/heads/main"`)でリポジトリの
  実際の中身を直接確認するか、`git fetch`を再実行してみること(再実行で
  キャッシュが解消されて正しいコミットが取得できる場合がある)。
- **担当ブランチがGitHub上に存在しない場合、既にPRがマージ済みで削除
  されている可能性が高い**:`git fetch origin <指定ブランチ名>`が
  `couldn't find remote ref`で失敗した場合、`git ls-remote origin`で
  実在するブランチ一覧を確認すること。担当ブランチが本当に無ければ、
  最新の`main`から同じ名前で再作成し、そのブランチで新しいPRを作る
  (マージ済みの古いブランチを再利用しようとしない)。
- **ヘッドレステストは`image/`・`sound/`をシンボリックリンクした
  一時ディレクトリで行うと、セーブファイルを汚さずに済む**:
  モジュール冒頭で`pygame.image.load("image/...")`のように相対パスで
  画像を読み込んでいるため、セーブファイル分離のために作業ディレクトリを
  一時ディレクトリに`chdir`すると`FileNotFoundError`になる。
  `os.symlink(repo内のimage, tmpdir/image)`・同様に`sound/`もリンクして
  から`chdir`すれば、大きなアセットフォルダをコピーせずに済み、
  `savefile*.json`等のテスト用セーブデータもリポジトリ外の一時領域に
  閉じ込められる。
- **新しいフロア特性のアイデアが尽きてきたら、既存の`modifier_*()`関数の
  「逆」を考えると見つけやすい**:今回追加したTorchlit Floor(視界+2)は、
  既存のFoggy Floor(視界-2)を実装している`modifier_vision_delta()`に
  分岐を1つ足すだけで実装できた。新しい`modifier_*()`関数をゼロから
  設計するより、既存の関数が持つパラメータの符号を反転させるだけで
  「対になる特性」を安全に追加できる場合が多い。
- **新しい敵モンスターを追加する場合、画像スロットが埋まっていても
  「既存の絵に色を掛け合わせる」手で新モンスターを成立させられる**:
  通常敵の画像スロット(`image/enemy0.png`〜`enemy29.png`+個別ファイル名)は
  rev163時点ですべて使用済みで空きが無い。Hugging Face MCP経由の画像生成
  自体は成功する(`gr1_z_image_turbo_generate`等でプレビューは見える)が、
  生成画像を配信しているhf.spaceホストへの接続はこのセッションの
  ネットワークポリシーで403拒否され、ローカルに保存する手段が無かった
  (`curl`/`WebFetch`いずれも同じホストで失敗。ポリシー拒否はリトライ・
  回避せず、報告のうえ別の実装に切り替えるのが正しい対応)。この
  ケースでは、Elite個体(`ELITE_TINT`)やドッペルゲンガー
  (`DOPPELGANGER_TINT`)と同じ`tint_surface()`による色調変更を新モンスター
  にも使い、既存の敵画像を色違いとして流用することで、新規アセットの
  取得に失敗しても新モンスター追加そのものは諦めずに実装できた
  (rev163の「Voidforged Golem」= 紫色に染めたIron Golem)。将来また
  同様に画像取得がブロックされた場合も、まずこの色替え手法が使えないか
  検討するとよい。
- 自動開発を行っている実行環境には `gh` CLI が入っておらず、GitHub操作
  (PR作成・確認・マージ等)は GitHub MCP サーバー経由のツールで行っている。
  もし別環境で `gh` コマンドが使えない場合は、PATH の通った `gh` の
  フルパスを確認するか、GitHub MCP/API 経由の代替手段に切り替えること。
- テスト用の実行環境には `pygame` がプリインストールされていないことがある。
  `py_compile` は問題なく通っても、ヘッドレス起動テスト
  (`SDL_VIDEODRIVER=dummy`)の前に `pip install pygame` が必要になる場合がある。
- ヘッドレス動作確認で `runpy.run_path()` を使うと戻り値の名前空間が
  実際にロードされたモジュールの `__globals__` とは別物(コピー)になり、
  グローバル変数を書き換えても関数側の挙動に反映されない。フロア特性など
  グローバル状態に依存するロジックを対話的にテストする場合は
  `importlib.util.spec_from_file_location` + `module_from_spec` +
  `exec_module` で実モジュールとしてロードすること。
- 効果音配列 `se`(`pygame.mixer.Sound` のリスト)は `main()` 関数内で
  ローカル変数として作られており、`global se` 宣言もされていないため、
  `main()` の外で定義された関数(`move_player()` など)から直接
  `se[n].play()` を呼ぶと `NameError` になる(実際にこのPRで一度踏んだ)。
  `main()` の外から効果音を鳴らしたい場合は、既存の
  `achievement_sound_pending` と同じ「フラグを立てて `main()` の
  メインループ側で再生する」パターンに倣うこと。
- `importlib` で実モジュールとしてロードする際、モジュール冒頭で
  `pygame.image.load(...).convert_alpha()` を呼んでいる箇所があるため、
  `pygame.init()` と `pygame.display.set_mode((880, 720))` を
  **`exec_module()` より前に**実行しておかないと
  `pygame.error: video system not initialized` で読み込みに失敗する。
- `main()` は `while True` の無限ループなので、ヘッドレスで動作確認する際は
  `pygame.event.get` を数十フレーム分だけ空リストを返し、その後
  `pygame.QUIT` イベントを1件返すダミー関数に差し替えると、
  `sys.exit()` 経由でクリーンに抜けられる(戻り値は`SystemExit`として
  捕捉する)。
- **新しいrevファイルを作る前に、他にまだマージされていないPRが同じ
  rev番号や似たアイデアを予約していないか確認すること**:このリポジトリは
  1時間ごとに複数の自動実行が並行して走ることがあり、`main`にマージ済みの
  最新rev番号だけを見て次の番号を決めると、別のまだオープンなPRが同じ
  ファイル名(例:`dungeon_rev144.py`)や同じ方向性の特性・実績(例:
  遭遇率を上げるフロア特性)をすでに提案していて、後からadd/addの
  コンフリクトや内容の重複が起きることがある。作業を始める前に
  GitHub MCPの`list_pull_requests`(`state: "all"`)でオープン中のPRの
  タイトル・提案ファイル名を確認し、被りそうならアイデアを変える
  (番号自体は慣例どおり「mainの最新+1」のままでよいが、機能内容は
  オープンPRと重複しないものを選ぶ)。
- このPRのテスト中、`draw_crit_flash()` の透明度計算が
  `crit_flash_timer > CRIT_FLASH_FRAMES` の場合(コンボフィニッシャー
  `+4`・自己ベストコンボ更新`+2`)に255を超えてしまい、
  `pygame.Surface.fill()` が `ValueError: invalid color argument` で
  クラッシュする不具合を発見した(rev133時点から存在していた既存バグ)。
  0〜255の範囲を超えうるアルファ値/色成分は、ダメージポップアップの
  実装と同様に必ず `max(0, min(255, ...))` でクランプすること。
  「起動するか」だけでなく、実際にトリガー値を再現して関数を呼ぶ
  ピンポイントなテストをしないと見つからない類のバグなので、
  新しい演出を追加・変更したときは可能な範囲で実際の値を使った
  再現テストも行うとよい。

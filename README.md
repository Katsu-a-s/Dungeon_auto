# Dungeon Auto

Python + [pygame](https://www.pyga.me/) 製のローグライク風ダンジョン探索ゲーム。
メインファイルは **`dungeon_rev218.py`**(単一ファイル構成、約13,000行)。
過去のバージョン(`dungeon_rev100.py`〜)もすべて残してあるが、実行・動作確認は
常に**一番番号が大きいファイル**で行う(過去のrevファイルは削除せずすべて
残す運用のため、ディレクトリ内には複数バージョンが並存している)。

> このリポジトリは Claude によるルーティン作業(1時間ごとの自動開発)で
> 少しずつ機能追加・改善が行われています。このREADMEも実装状況に合わせて
> 逐次更新されます。

## このゲームってどんなゲーム?(はじめての人向け)

`Dungeon Auto` は、迷路になった地下ダンジョンを歩き回って、モンスターと戦い
ながら深い階を目指す1人用のRPGです。難しい前提知識はいらず、次のことを
繰り返すだけで遊べます。

1. 矢印キーでダンジョンの中を歩いて探索する(壁にぶつからないように迷路を進む)。
2. モンスターに出会ったらバトル開始。攻撃・ポーション(回復)・爆炎石(強力な
   一撃)・防御・逃走などのコマンドから選んで戦う。
3. 階段を見つけたら次の階へ。10階ごとに強いボスが待っている。
4. レベルアップしてスキルを覚えたり、宝箱からアイテムを手に入れたりしながら、
   全3ステージ×30階(合計90階)のクリアを目指す。全クリア後は、育てたキャラの
   ままさらに奥まで潜り続けられる「エンドレス・ディープス」にも挑戦できる。

ゲームオーバーになってもレベルや装備は引き継がれないシンプルなローグライク
寄りのルールですが、実績(称号)やコレクション要素(図鑑)がたくさんあるので、
1回のプレイが短くても「もう1回だけ」とやり込みたくなるように作られています。
操作に迷ったら、タイトル画面右上の `[F1] Help` からいつでも操作方法を確認できます。

## 遊び方

```bash
pip install pygame
python3 dungeon_rev218.py
```

- 画面サイズ 880x720、キーボード + マウス操作対応。
- セーブデータ等(`savefile*.json` / `autosave.json` / `settings.json` など)は
  実行時にリポジトリ直下へ自動生成されます(`.gitignore` 済みでコミット対象外)。

## 操作方法

ゲーム内タイトル画面右上の **`[F1] Help`** ボタン(または `F1` キー)から、
いつでもコントロール一覧を確認できます。

| 場面 | キー | 内容 |
|---|---|---|
| タイトル | 矢印キー / `Space` | メニュー選択 / ゲーム開始 |
| タイトル | `T` | 難易度切り替え(Easy/Normal/Hard/Nightmare※/Abyss※※/Oblivion※※※※) |
| タイトル | `N` | キャラクター選択 |
| タイトル | `G` | ゲームデータ(ロード/コンティニュー/設定) |
| タイトル | `R` | 記録(実績/統計/図鑑/エコーバトル/デイリーランキング) |
| タイトル | `Y` | デイリーチャレンジ開始 |
| タイトル | `A` | 闘技場(Arena of Trials、いつでも挑戦できる連戦サバイバル) |
| タイトル | `U` | ボスラッシュ(Boss Rush、全9体のステージボスを連戦) |
| タイトル | `H` | 隠しステージ(全クリア後に出現) |
| タイトル | `F1` | ヘルプ画面 |
| ダンジョン探索 | 矢印キー | 移動 |
| ダンジョン探索 | `Q` | セーブメニュー |
| ダンジョン探索 | `K` | スキルツリー |
| ダンジョン探索 | `P` | ペット情報(仲間がいる時のみ) |
| ダンジョン探索 | `I` | ポーション使用 |
| バトル | `A`/`P`/`B`/`R`/`D`/`F`/`U`/`C` | 攻撃/ポーション/爆炎石/逃走/防御/集中/必殺技(コンボ5必要)/反撃 |
| バトル | `Up`/`Down`, `Space`/`Enter` | コマンド選択/決定 |
| 共通 | `Esc` | 戻る・キャンセル |
| 共通 | `M` | 全音声(BGM/SE)をミュート/解除 |

※ Nightmare難易度は、Hardクリア実績(hard_clear)を解除するまでは
`T`キーでの切り替えサイクルに出てきません。まずHardで全ステージクリアして
アンロックしてください。

※※ Abyss難易度は、さらにその上の最上位難易度です。Nightmareクリア実績
(nightmare_clear)を解除するまでは選べません。しかも他の難易度と違い、
**このモードで力尽きるとオートセーブそのものが消え、続きからやり直せません**
(手動セーブも使えません)。まさに一発勝負を求める玄人向けの挑戦です。

※※※※ Oblivion難易度は、Abyssよりさらに上の最終難易度です。Abyssクリア
実績(abyss_clear)を解除するまでは選べません。Abyssと同じくパーマデス
(力尽きるとオートセーブが消え、手動セーブも不可)ですが、その代わり敵を
倒し進んだ時のアイテム運・経験値はAbyssよりもさらに気前よくなる、
「一番危険だが、生き延びれば一番おいしい」玄人向けの最終試練です。

※※※ 全3ステージをクリアすると出る「GAME CLEAR!」画面で `[X]` キーを押すと、
そのままのレベル・スキル・所持品で91階以降の「エンドレス・ディープス」に
突入できます(`[Space]`キーならこれまで通りタイトルに戻ります)。

## 現在の実装状況

### ダンジョン・進行
- **新フロア特性「Gilded Floor(黄金の床)」**:ダンジョン各所に
  まれに(通常floor5以降14%)出現する聖なる鍵と封印の宝物庫の組は、
  これまでどのフロア特性からも一切影響を受けない数少ない一点だった
  (Charmed/Forgefire/Undertow Floorが埋めてきた「フロア特性が及んで
  いない一点」の穴を、今回は聖なる鍵の宝物庫の出現確率に適用した)。この
  フロアでは出現確率が+18%pt上乗せされる(14%→32%、フロア特性は
  87種類→**88種類**)。
- 新フロア特性「Rusted Floor(錆びの床)」:新モンスター
  「Rust Golem」(通常攻撃が状態異常「錆蝕」を与える、詳細は「バトル」を
  参照)を追加したのに合わせ、その錆蝕付与確率を+20%pt上乗せする専用の
  フロア特性を同じrevで用意した(Bloodslick/Frostgrip/Mournful Floorが
  行ってきたのと同じパターン)。フロア特性は86種類→**87種類**。
- 新フロア特性「Cascading Floor(連鎖の床)」:新設した
  主人公タイプ「Virtuoso(名手)」(詳細は「キャラクター・成長」を参照)は、
  コンボを高く積み上げた末に発動する「コンボ・フィニッシャー」を軸にした
  個性だが、そのフィニッシャーの威力倍率(通常x2.2固定)はこれまでどの
  フロア特性からも一切影響を受けない数少ない一点だった(Warbound/
  Mournful/Undertow Floorが新システム導入と同じrevで埋めてきた「フロア
  特性が及んでいない一点」の穴と同じパターンを、今回はコンボ・
  フィニッシャーに適用した)。このフロアではコンボ・フィニッシャーの
  威力がx2.7に上がり、Virtuosoに限らずどの主人公でも高コンボからの
  一撃がより派手に決まる(フロア特性は85種類→**86種類**)。
- 新しい探索要素「奈落の縦穴(Abyssal Shaft)」:近道(分岐ルート、
  フロア5以降)は「寄り道の先で報酬を得ながら1フロア飛ばす」仕掛けだったが、
  報酬は要らないからとにかく速く深層へ進みたい、という「速さ最優先」の
  遊び方に応える仕掛けがまだ無かった。フロア15以降にまれに出現するこの
  床を踏むと、`[Y]`/`[N]`で確認が入り、`[Y]`を選ぶと今いるフロアの残りの
  探索・経験値・宝箱をすべて諦める代わりに、通常の階段よりも3フロアも
  余分に一気に深層へ進める(見た目は不安定な裂け目の画像を深い漆黒紫に
  染め直した色違い、これまでと同じ既存素材の色違い方針)。ボスがいる階を
  飛び越えてしまう組み合わせでは安全のため出現しない。初めて飛び込むと
  実績「Abyssal Shaft Diver」、通算10回で称号付きの「Abyssal Shaft
  Conqueror」(称号: the Depth Diver)が解除される(実績は161種→
  **163種**のうち2つ)。
- 新フロア特性「Undertow Floor(深潮の床)」:上記の奈落の
  縦穴はフロア15以降でも低確率でしか出現せず、狙って使いたいプレイヤーが
  何十階も見つけられずにいることがある。Charmed/Forgefire Floorが護符の
  祠・灯火の鍛冶場に対して行ったのと同じ「確率ではなく確定にする」軸を、
  新システム導入と同じrevで用意した。このフロアでは奈落の縦穴が必ず1つ
  出現する(ボス階をまたいでしまう組み合わせでは、この特性であっても
  出現しない安全策は変わらない)。フロア特性は84種類→**85種類**。
- **新しい最終難易度「Oblivion(忘却)」**:プレイヤーから「ゲームの
  難易度をもっと深く、玄人用のモードも増やしてほしい」という声を受け、
  Abyss(パーマデスの最上位難易度)のさらに上に新しい難易度を追加した。
  Abyssクリア実績(abyss_clear)を解除して初めて`T`キーの切り替えサイクルに
  現れる。Abyssと同じくパーマデス(力尽きるとオートセーブが消え、手動
  セーブも不可)を受け継ぎつつ、Abyssが確立した「戦闘の脅威だけを引き上げ、
  進行速度側は過度に罰しない」設計方針をさらに一段推し進め、敵の強さは
  Abyss以上に厳しくなる代わりに、経験値・アイテム運はAbyssよりもさらに
  気前よくした。「一番危険だが、生き延びれば一番おいしい」を極めた、
  難易度Easy〜Abyssに続く6段階目の頂点。専用の実績「Oblivion Walker」
  (称号: the Oblivion Walker)も追加した。
- 新フロア特性「Warbound Floor(戦地の床)」:秘宝「Slayer's
  Emblem」(ボス級の相手へのダメージ+15%、詳細は「キャラクター・成長」を
  参照)は、これまでどのフロア特性からも一切影響を受けない数少ない一点
  だった(Venomfang/Stormbound/Bloodslick/Frostgrip Floorが新システム
  導入と同じrevで埋めてきた「フロア特性が及んでいない一点」の穴と同じ
  パターンを、今回はボス戦ダメージに適用した)。このフロアで挑むボス級の
  相手(通常のステージボス・エコーバトル・ボスラッシュ)には、ダメージが
  さらに+15%pt上乗せされる(フロア特性は82種類→**83種類**)。
- **新フロア特性「Mournful Floor(哀切の床)」**:新モンスター
  「Wailing Banshee」(通常攻撃が状態異常「哀弱」を与える、詳細は
  「バトル」を参照)を追加したのに合わせ、その哀弱付与確率を+20%pt
  上乗せする専用のフロア特性を同じrevで用意した(Bloodslick Floor/
  Frostgrip Floorが行ったのと同じパターン)。フロア特性は83種類→
  **84種類**。
- 新しい特殊床「試練の石碑(Trial Post)」:フロア6以降にまれに
  出現する新しい仕掛け。不安定な裂け目(Rift)と同じく、足を踏み入れると
  必ず格上の(エリート)敵との戦闘になるハイリスクな床だが、裂け目の報酬が
  ポーション・爆炎石・食料という消費アイテムに留まるのに対し、この石碑は
  勝利すると持っていない秘宝(Relic、全17種)を1つ**確実に**手に入れられる
  (通常のボス撃破時の秘宝ドロップはあくまで確率任せなのに対し、こちらは
  挑む代わりに結果を確定させる、初めて「秘宝コレクションを狙って埋める」
  ための仕掛け)。すでに秘宝を全種集めきっている場合は、代わりにまとまった
  ポーション・爆炎石・食料が手に入るので手ぶらに終わることはない。見た目は
  守護者の像の画像を紅蓮色に染め直した色違いを使っている(新規スプライトは
  この実行環境のネットワーク制限でHugging Face MCP経由の生成画像を保存
  できないため、既存素材の色違いで見分けをつける、これまでと同じ方針)。
  初めて突破すると実績「Trial Survivor」、通算10回突破すると称号付きの
  「Trial Master」(称号: the Trialbreaker)が解除される(詳しくは
  「やり込み要素」を参照)。
- 新フロア特性「Fleeting Floor(陽炎の床)」:黄金の像の台座を
  持ち上げた後に追いかけてくる転がる巨石は、これまで追跡が続く歩数
  (通常22歩)がどのフロア特性からも一切影響を受けない数少ない一点
  だった。既存修飾子の符号反転ではなく、初めて「追跡そのものの長さ」を
  短くする新しい方向の「当たり」特性として、このフロアでは追跡が8歩短く
  なり、それだけ安全に像の報酬を持ち帰りやすくなる(フロア特性は81種類→
  **82種類**)。
- **新モード「ボスラッシュ(Boss Rush)」**:タイトル画面から`[U]`キーで
  いつでも挑戦できる新しいサイドコンテンツ。闘技場(Arena of Trials)が
  「同じ雑魚敵をどんどん強くしながら削る持久戦」で退くか攻めるかの駆け引きを
  持つのに対し、こちらは全9体のステージボス(フロア10/20/…/90)を、間に
  最大HPの35%回復を挟みながら一体ずつ順番に連戦する「格上の敵と立て続けに
  戦う瞬発力型」の挑戦として性格を分けた。押し引きの選択は無く、全員倒すか
  力尽きるまで進むだけのシンプルな構成で、9体を全て倒し切ると
  ポーション・ブレイズジェム・最大HPのまとまった報酬と、称号付き実績
  「Boss Rush Champion」(称号: the Boss Slayer)が手に入る。初めて1体目を
  倒した時点でも実績「Boss Rush Starter」が解除される(詳しくは
  「やり込み要素」を参照)。タイトル画面の闘技場ボタンの隣に自己ベスト
  (通算で何体連続で倒せたか)も常時表示される。
- **新フロア特性「Frostgrip Floor(氷結の床)」**:今回新設した
  新モンスター「Permafrost Wyrm」(通常攻撃が状態異常「凍結」を与える、
  詳細は「バトル」を参照)を追加したのに合わせ、その凍結付与確率を
  +20%pt上乗せする専用のフロア特性を同じrevで用意した(Venomfang Floor/
  Stormbound Floor/Bloodslick Floorが行ってきたのと同じパターン。
  なお同名の"Frostbound Floor"(敵の攻撃力-15%)は既に別の特性として
  存在していたため、内部キーの衝突を避けてこちらは"Frostgrip Floor"と
  いう別名にしている)。フロア特性は80種類→**81種類**。
- **新フロア特性「Bloodslick Floor(血滑りの床)」**:新モンスター
  「Bloodthorn Revenant」(通常攻撃が状態異常「出血」を与える、詳細は
  「バトル」を参照)を追加したのに合わせ、その出血付与確率を+20%pt
  上乗せする専用のフロア特性を同じrevで用意した(Venomfang Floorが毒の
  秘宝Serpent's Fangに対して行ったのと同じパターン)。フロア特性は
  79種類→**80種類**。
- **新モード「闘技場(Arena of Trials)」**:タイトル画面から
  `[A]`キーでいつでも挑戦できる、連戦サバイバル形式の新しいコンテンツ。
  隠しステージ・True Depthsのような「全クリア後にしか挑めない一発勝負」
  とは違い、条件は一切無く、今のセーブキャラのステータス(未作成なら
  即席ステータス)を持ち込んで通常のダンジョン敵と連戦できる、腕試しの
  場として新設した。1ラウンド倒すごとに、次のラウンドに挑む(敵が
  少しずつ強くなるハイリスク)か、ここで退いて報酬(ポーション・
  ブレイズジェム)を持ち帰る(ローリスク)かを選べる「攻めるか、退くか」
  の駆け引きが新しい。倒れてしまっても、最後の1つ手前まで勝ち抜いた分の
  報酬はきちんと持ち帰れる。タイトル画面には自己ベストのラウンド数も
  常時表示される。初めてラウンドを突破すると実績「Arena Novice」、
  1回の挑戦でラウンド10まで到達すると称号付きの「Arena Gladiator」
  (称号: the Gladiator)が解除される(詳しくは「やり込み要素」を参照)。
- 新フロア特性「Forgefire Floor(灯火の床)」:ダンジョン各所にまれに
  (通常floor6以降12%)現れる「灯火の鍛冶場(Ember Forge)」は、Molten
  Floorのおかげで変換レート(ブレイズジェム→永続STR)には既に触れられて
  いたが、その鍛冶場そのものが出現するかどうかには、Charmed Floorが
  護符の祠に適用したのと同じ「確率ではなく確定にする」軸がまだ及んで
  いなかった。このフロアでは灯火の鍛冶場が必ず1つ出現するようにした
  (フロア特性は78種類→**79種類**)。
- 新フロア特性「Stormbound Floor(雷雲の床)」:秘宝「Thunderclap Idol」
  (攻撃が敵を気絶させる、詳細は「キャラクター・成長」の秘宝システムを
  参照)に合わせ、その気絶付与確率を+15%pt上乗せする専用のフロア特性を
  同じrevで用意した(Venomfang Floorが毒の秘宝Serpent's Fangに対して
  行ったのと同じパターン)。フロア特性は77種類→**78種類**。
- 全 **3ステージ × 30階 = 90階**(`STAGE_LENGTH`/`STAGE_COUNT`)+ 全クリア後の隠しステージ(ボス戦)。
- 新しい探索要素「近道(Shortcut Passage)」:直近数回
  (rev190〜199)は新モンスター・新プレイアブルキャラクター・新しい秘宝軸・
  新実績が中心で、新しいマップ要素はrev183以来しばらく出ていなかった
  ため、今回はプレイの幅を広げる大きめの要素として、既存ステージの
  中に隠された「分岐ルート」を追加した。フロア5以降、隠し壁と同じ
  ように壁の中に低確率で「近道の入り口」が隠れており、隣接すると
  自動的に見つかる(隠し壁と違い、見た目にも琥珀色に光るので発見後は
  一目で分かる)。踏み込むと、宝箱2個とモンスターとの遭遇2箇所がある
  細い一本道の小さなボーナスエリアへ移動し、突き当りの階段を使うと
  今いたフロアの1つ先を丸ごと1つ飛ばして、その次のフロアまで
  一気に進める。飛ばしたフロアの探索・経験値・宝箱は手に入らない代わりに、

  「威力」を直接伸ばす特性が無かったため、新しい方向性として追加した。
- **新フロア特性「Opulent Floor(豪奢の床)」**:このフロアでは宝箱の出現重みが
  約2倍になり、フロアあたりの宝箱の数が増える。従来のフロア特性はアイテムの
  「質」(bountiful/cursed)や遭遇頻度(veiled)には関わっていたが、宝箱そのものの
  「数」を直接増やす特性が無かったため、新しい方向性として追加した。
- ショートカット移動・キー長押しでの連続移動、氷床での自動スライドなど操作性の作り込み。
- 20種類以上の特別部屋(モンスターの巣・祠・裂け目・賭博場・キメラ部屋・血月イベント等)を
  フロアごとに抽選配置。
- **新しい仕掛け「灯火の鍛冶場(Ember Forge)」**:フロア6以降にまれに
  出現する鍛冶台のマス。爆炎石(Blaze Gem)を持って足を踏み入れると、
  持っている爆炎石を全部使って、その代わりに攻撃力(STR)がずっと上がる
  永続強化を受け取れる。爆炎石は1本も無い状態で踏んでも何も起きず、
  鍛冶場はそのまま残るので、爆炎石が貯まってから改めて使いに戻ることもできる。
  「ここぞという場面のために爆炎石を温存するか、思い切って自分の力に
  変えてしまうか」を選べる、今までに無かった新しい駆け引きの仕掛け。
  10回使うと新しい称号「the Master Smith」も手に入る。
- **新しい特別マス「旅の吟遊詩人(Traveling Bard)」**:フロア6以降に
  まれに出現するマス。今回追加した「仲間の絆」(下記キャラクター・成長の
  項目を参照)によって同じ仲間と長く付き合う意味が増した一方、孵化した
  仲間はこれまで一周を通してずっと固定で、気に入らない仲間が孵ってしまっても

  一目でわかる)。Lv40に到達すると新実績「Legend」(称号: the Legend)も
  解除される。
- **秘宝(Relic)システム**:今までプレイヤーの永続強化は
  「ボス撃破時の固定ボーナス」「指輪・アミュレットなどの宝箱アイテム」しか
  無く、探索を重ねるほど増えていく所持品・収集要素が無かった。通常のボス
  (10階ごと、エコーバトルは対象外)を倒すと、30%の確率で未所持の秘宝を
  1つ手に入れる。全13種類(Ember Charm/Phantom Lens=会心率上昇、
  Lucky Clover/Golden Compass=アイテム発見率上昇、Sage's Quill/
  Ancient Tome=獲得EXP上昇、Swift Sandals/Windwalker Charm=移動速度上昇、
  Featherlight Cloak=逃走成功率上昇、Serpent's Fang=攻撃が敵を毒にする、
  Warden's Bulwark=反撃(Counter)の被ダメージ軽減量・反撃ダメージ上昇、
  Vital Charm=歩数ごとの受動回復量アップ、
  Thunderclap Idol=攻撃が敵を1ターン気絶させる)
  あり、手に入れるたびに恒久的な
  パッシブ効果が積み重なっていく。タイトル
  画面の記録メニュー(`[R]`→`[P] Relics`)から、今までに見つけた秘宝の
  一覧(図鑑と同じく未発見は「???」表示)といつでも確認できる。初めて
  1つ手に入れると実績「Relic Finder」、全種類集めると「Relic Collector」
  が解除される。
- 秘宝に新しい軸「受動回復」を追加「Vital Charm」:秘宝は
  会心率/アイテム発見率/獲得EXP/移動速度/逃走成功率/毒付与/反撃強化の
  7軸すべてが探索・逃走・戦闘のいずれかを底上げする軸で、歩数ごとに
  少しずつHPが回復する「受動回復」は、これまでフロア特性(Blessed Floor=
  2倍/Barren Floor=半減)にしか触れられておらず、秘宝側から底上げする
  軸がまだ無かった。新しい秘宝「Vital Charm」を持つと、歩数ごとの
  受動回復量が+40%される(秘宝は11種類→**12種類**)。記録メニューの
  秘宝一覧画面も12種類分表示できるよう行間を40px→36pxに詰めた。
- **秘宝に初めて「反撃(Counter)」を強化する軸を追加

  逃走成功率/毒付与の6軸すべてが、通常攻撃・逃走・探索など既存コマンドの
  底上げばかりで、rev174で追加したバトルコマンド「反撃(Counter)」には
  フロア特性(Bulwark Floor)しか触れておらず、秘宝側から強化する軸が
  まだ無かった。新しい秘宝「Warden's Bulwark」を持つと、Counterの被
  ダメージ軽減量・反撃ダメージの両方が+25%される。Bulwark Floorと同じ
  軸を秘宝側からも底上げする構成のため、フロアとこの秘宝を両方組み合わせる

  秘宝一覧画面も11種類分表示できるよう行間を44px→40pxに詰めた。
- **秘宝に新しい軸「移動速度」を追加**:秘宝は会心率/アイテム
  発見率/獲得EXPの3軸がそれぞれ2種類ずつという、既存の軸を数値違いで
  増やすだけの構成が続いていたため、まだどの秘宝も触れていなかった
  探索中の移動速度という新しい軸にSwift Sandals(+8%)/Windwalker

  秘宝一覧画面も8種類分表示できるよう行間を60px→48pxに詰めた。
- **秘宝に新しい軸「逃走成功率」を追加(Featherlight Cloak)**:
  秘宝は会心率/アイテム発見率/獲得EXP/移動速度の4軸あったが、戦うのが
  不利な時に頼る「逃げる(Run)」コマンドの成功率だけは、これまでフロア

  でしか触れられていなかった。新しい秘宝「Featherlight Cloak」

  逃げ足が速くなるようにした(秘宝は8種類→9種類)。
- **秘宝に初めて「敵に影響する」軸を追加「Serpent's Fang」**:
  秘宝は会心率/アイテム発見率/獲得EXP/移動速度/逃走成功率の5軸あったが、
  すべて「プレイヤー自身を強くする」自己バフで、秘宝側から敵に影響を

  通算10体倒すと「Serpent Charmer」が解除される。

  色で点滅する重体警告を追加。ステータスパネルのHP数値(残り50%でオレンジ→
  残り20%で赤)と同じ「危険度が上がるほど早く/強く気づける」考え方を食料にも
  揃え、飢餓ダメージが始まる直前の緊急度をより正確に伝えられるように改善した。
- **防御の薬(Defense Pill)の残り僅か/切れ表示**:画面左下のステータス
  パネルで、防御の薬の所持数が0個になるとポーション/爆炎石と同じ灰色の「0」
  表示に、残り1個になるとオレンジ色に点滅するアイコン表示になるように変更。
  従来はポーション・爆炎石には在庫切れ/残り僅かの警告表示があったのに、
  同じ消費アイテムである防御の薬だけアイコン表示のみで色分けが無く、3種類の
  消費アイテムの中で気づきにくい状態だったため、表示ルールを揃えて改善した。
- **ステータスパネルのHP数値、割合に応じた色分け**:画面左下のHP表示
  (`◯/◯`)が、従来はHPが絶対値で10を切った瞬間だけ赤く点滅していた。
  最大HPが大きいGuardianなどではその頃には手遅れに近く、逆に序盤の低い
  最大HPでは過敏に点滅していたため、画面端の低HP警告(残り20%)と同じ
  割合基準に揃え、赤で点滅する手前の残り50%からオレンジ色で予兆を
  出すように変更。他の数値(食料・ポーション・爆炎石)の事前警告と
  同じ考え方で、危険に気づくタイミングを早めた。
- **ボスHPバーのフェーズ2ラインの目印**:ボス戦・エコーバトルでは、
  HPバーの50%位置(フェーズ2/激怒に切り替わるライン)に薄い縦線を常時表示
  するように。従来はHPが実際に50%を切った瞬間に初めて「ENRAGED」だと
  わかったが、戦闘開始時点からあとどれだけ削ればフェーズ2に入るのか目視で
  見通せなかったため、事前に狙いを定められるように追加した。
- タイトル画面はマウスクリック操作にも対応した階層メニュー(つやのあるボタンUI)。
- BGM/SE音量を個別調整できる設定画面 + `M`キーでのワンタッチ全ミュート切り替え。
- **画面シェイクのON/OFF設定**:設定画面(`[O] Settings`)に「Screen Shake」
  トグルを追加。被弾・クリティカル・コンボフィニッシャー時の画面シェイク演出は
  臨場感を高める一方、酔いやすい・目が疲れやすいプレイヤーには不快な場合が
  あったため、いつでもオフにできるアクセシビリティ設定として追加した(設定は
  `settings.json` に永続化)。
- **画面フラッシュのON/OFF設定**:設定画面に「Screen Flash」トグルを
  追加。クリティカルヒット・コンボフィニッシャー・自己ベストコンボ更新・
  希少アイテム発見の際に画面全体が光るフラッシュ演出は爽快感を高める一方、
  光過敏なプレイヤーには負担になりうるため、Screen Shakeと同様にいつでも
  オフにできるアクセシビリティ設定として追加した(設定は`settings.json`に
  永続化)。
- 実績・統計一覧のスクロール対応、図鑑詳細のクリックプレビュー。
- **ヘルプ画面(`[F1]`)**:操作方法をタイトル/探索/バトル別にまとめて確認可能。
- **低HP警告**:残りHPが最大値の20%を切ると、探索中・バトル中を問わず
  画面端が心拍のように速く脈打つ赤い縁取りで警告(崩落演出とは脈拍の速さで区別)。
- **食料残量の事前警告**:従来は食料が完全に0になった瞬間だけ数値が
  赤く点滅していたため、飢餓ダメージを受けてから慌てて食料を探すことが
  あった。残り30以下になった時点でオレンジ色に点滅するようになり、0になる
  前に余裕を持って食料(ポーション交換や落ちている食料アイテム等)を
  確保できるように改善。
- **ポーション切れの表示強調**:画面左下のステータスパネルで、所持
  ポーション数が0になると、他の数値と同じ白色ではなく灰色に変わるように
  なった。従来は「0」という数字も他の数値と見た目が同じで見落としやすかった
  ため、パッと見で「もう回復手段が無い」ことに気づけるようにした。
- **爆炎石切れの表示強調**:同じステータスパネルで、爆炎石の所持数が
  0になった場合もポーションと同様に灰色表示になるように変更。従来は
  ポーションのみ灰色化されており、もう一方の消費アイテムである爆炎石は
  0になっても他の数値と見分けが付かなかったため、表示ルールを揃えて改善した。
- **ポーション/爆炎石の残り僅か事前警告**:画面左下のステータス
  パネルで、ポーション・爆炎石の残り数が1個になった時点で、食料の事前警告
  (残り30以下でオレンジ点滅)と同じ考え方でオレンジ色に点滅するように
  なった。従来は0個になって灰色化するまで数値の見た目に変化が無く、
  「あと1回で尽きる」という状況に気づきにくかったため、0になる前に
  ワンテンポ早く気づけるように改善した。
- **クリティカル/コンボフィニッシャー演出**:クリティカルヒットやコンボ
  フィニッシャーが発動した瞬間、画面全体が短く光るフラッシュ演出を追加し、
  攻撃の爽快感を強化(フィニッシャーはより長く・ピンクがかった色で発光)。
- **ボス階警告**:未撃破のボスがいるフロアに足を踏み入れると、
  「Welcome to floor」表示と一緒に脈打つ赤文字で警告メッセージが表示され、
  階段に着く前にポーションや爆炎石の準備をする猶予が生まれるように。
- **ボス階までの残り階数表示**:ボス階まで残り3階以内になると、
  探索中のHUDに「Boss floor in N」と表示されるように。従来はボス階に
  足を踏み入れた瞬間にしか警告が無く、直前まで準備するタイミングが
  分からなかったため、少し早めに心構えできるように追加した。
- **画面シェイク演出**:被弾時・クリティカルヒット・コンボフィニッシャー発動時に
  画面が数フレームだけ小刻みに揺れるようになり、打撃の重みを強化(ボスの
  フェーズ2/激怒中に被弾すると揺れが一段大きくなる)。
- **ダメージポップアップ**:攻撃がヒットした瞬間、命中した対象(敵/プレイヤー)の
  頭上にダメージ数値がふわっと浮かび上がってフェードアウトするように。固定の
  メッセージ欄だけでは伝わりにくかった「どこで何が起きたか」を視覚的に補強し、
  クリティカルヒットは金色・コンボフィニッシャーはピンク色で一回り大きく強調表示。
- **実績解除トースト**:実績を解除した瞬間、画面上部にバッジ画像付きの
  ゴールドのバナーが上からスライドインして「ACHIEVEMENT UNLOCKED!」と実績名を
  表示するように。従来は他の雑多な通知と同じ地味な1行テキストで、探索中/バトル中
  問わず気づきにくかったが、専用の演出にしたことで達成感がひと目で伝わるように
  なった(探索・バトル・メニューなどどの画面でも表示される)。
- **自己ベストコンボ更新演出**:バトル中に歴代最高コンボ数
  (プレイ統計の「Highest combo streak reached」)を更新した瞬間、
  「New best combo! x◯」というメッセージと共に、クリティカルヒットと同じ
  画面フラッシュ機構を金色で流用して光らせるように。従来は記録自体は
  裏で更新されていても画面上には何の合図も無く、コンボを伸ばす動機づけが
  弱かったため、更新の瞬間にひと目で気づけるように追加した(1バトルにつき
  演出は一度だけに絞り、連続ヒットのたびに出て煩わしくならないようにした)。
- 宝箱から指輪・アミュレットなど希少なアイテム(tier 5〜8)が出た時も、
  ポーションや爆炎石と同じく画面フラッシュ・ジングルの無い、静かな受け取りに
  なる(一時期は専用の金色フラッシュ+ジングルを付けていたが、演出が過剰
  という声を受けてrev172で廃止した)。

### サウンド・アセット
- `image/`:敵・ボス・アイテム・床・エフェクトなど201点のスプライト。
- `sound/`:ステージ別BGM(タイトル/フィールド/バトル、全ステージ分)+ SE + ジングル(レベルアップ/勝利/ゲームオーバー)。
- **【バグ修正】エコーバトルのBGMを再現対象フロアに合わせて変更**:
  図鑑から挑む「エコーバトル」(過去に倒したボスとの再戦、詳細は
  「やり込み要素」を参照)は、これまで闘技場(Arena of Trials)と
  全く同じ専用曲(Tolerance_Deviation.mp3)を共用していた。エコーバトルは
  「特定のフロアの過去のボス戦を再現する」場面なのに、闘技場の緊張感を
  煽る曲が流れるのは場面と噛み合っていなかったため、再現対象のフロアに
  対応する、そのステージ本来の戦闘曲(フィールドBGMと対になる
  `bgm_battle_for_floor`)を流すよう変更した。
- **【バグ修正】実績解除ジングル**:実績解除トーストが表示される瞬間、
  レベルアップジングルを再生して音でも達成に気づけるように。実は以前から
  このREADMEには同じ説明が書かれていたが、実装側ではトースト表示の状態を
  更新するだけでジングルはどこからも再生されておらず、記載と実装が
  食い違っていた(バナーのスライドインのみで、BGM/SEに気を取られていると
  見逃すことがあった)。今回、既存の`*_sound_pending`パターン(低HP警告等と
  同じ、フラグを立ててmain()側で消費するやり方)で実際にジングルが鳴る
  ようにした。新設した秘宝(Relic)入手時のトーストも同じジングルを再生する。
- 隠し壁を見つけて壁が開いた瞬間は、既存の攻撃音を発見の合図として
  短く鳴らす(一時期はふつうの宝箱を開けた瞬間にも効果音を鳴らしていたが、
  「合っていない」という声を受けてrev173で廃止し、ポーション・爆炎石等は
  従来通り無音で受け取る)。
- **低HP警告に効果音を追加**:残りHPが最大値の20%を切ると画面端が
  脈打つ赤い縁取りで警告する「Low HP Pulse」演出は、これまで見た目だけの
  演出で音が一切無く、画面の別の場所に気を取られていると気づきにくかった。
  実績解除ジングルと同じ「フラグを立てて次のフレームでmain()側が再生する」
  パターンで、警告状態に入った瞬間だけ既存の攻撃音を短く1回鳴らすように
  した(脈打つたびに毎回鳴らすと煩わしいため、警告に入った最初の一度だけ。
  HPが回復して警告が消えれば、次に再び危険域に入ったときにまた鳴る)。
  設定画面の「Low HP Pulse」トグルをオフにすれば、従来通り視覚・音とも
  演出無しにできる。

## 開発方針

- 既存のコードスタイル・命名規則を踏襲。
- 1回の自動実行あたりの変更は小〜中規模に留め、既存のゲームプレイを壊さない。
- 変更のたびに構文チェック(`py_compile`)・ヘッドレス動作確認
  (`SDL_VIDEODRIVER=dummy` での起動テスト)を実施。
- メインファイルは直接書き換えず、`cp` で複製してから編集する。
  `dungeon_revNNN.py` のNNNを1つ上げた新しいファイル名で保存し
  (例: `dungeon_rev123.py` → `dungeon_rev124.py`)、古いファイルは
  変更履歴としてそのまま残す。**実行・プレイ対象は常に番号が最大の
  ファイル。**バージョンごとの変更履歴をファイル名からも追えるようにする。

## 自動実行環境についてのメモ(つまずいた点)

- **オープンPRが`main`と同じ土台で完成していた場合は、先にマージしてから
  作業を始める**:2026-07-25のある実行時、着手前に`list_pull_requests`を
  確認したところ、別の並行実行が作った「Hardened Floor / Mimic Hunter /
  敵HP数値表示」のPR(#50、`dungeon_rev149.py`)がオープン中で、`main`の
  最新コミットをそのまま土台にしていて動作確認も済んでいた
  (`mergeable_state: clean`)。これを無視して自分も`dungeon_rev148.py`から
  `dungeon_rev149.py`を作ると、ファイル名が競合するだけでなく、マージ順序
  次第でPR #50の3つの変更が「番号が最大のファイルが実行対象」という運用
  ルールのもとで静かに巻き戻ってしまう危険があった。そのため、`rev149`は
  自分では作らず、先にPR #50をマージしてから、マージ後の最新`main`
  (`dungeon_rev149.py`)を土台に`dungeon_rev150.py`を作った。
- **2026-07-25の実行時、`main`の履歴が単一の"update"コミットに書き換えられて
  いた**:このルーティンとは別の操作で`main`のgit履歴が1コミットに整理され、
  それに伴い`dungeon_rev147.py`以前の旧revファイルもすべてリポジトリから
  削除されていた(ローカルクローンの`main`ブランチは書き換え前の古い履歴を
  指したままだったため、`git fetch origin main`を2回実行して強制更新
  (forced update)が来たことで気づけた)。ローカルの担当ブランチが偶然
  書き換え前の`main`と同じコミットを指していて紛らわしかったため、
  `git checkout -B <担当ブランチ> origin/main`で明示的に最新の`origin/main`
  へ揃え直してから作業を始めた。今後も、ローカルの`main`ブランチと
  `origin/main`のコミットIDが一致しているかを都度確認すること。
- **`git fetch origin main` の結果がGitHub上の実際の`main`より古く見える
  ことがある(プロキシ経由のgitキャッシュが原因)**:今回、ローカルの
  git(プロキシ経由)で`origin/main`をfetchすると、直前にマージされた
  はずのPR群が全く反映されていない、何十コミットも古い状態が返ってきた。
  そのまま信じて古い`main`を土台に作業すると、既にマージ済みの内容を
  重複実装したり、最新の`dungeon_revNNN.py`より古いファイルを次のrevの
  ベースにしてしまう危険がある。`main`が想定より古く見えたら、GitHub
  MCPの`get_file_contents`(例: `ref: "refs/heads/main"`)でリポジトリの
  実際の中身を直接確認するか、`git fetch`を再実行してみること(再実行で
  キャッシュが解消されて正しいコミットが取得できる場合がある)。
- **担当ブランチがGitHub上に存在しない場合、既にPRがマージ済みで削除
  されている可能性が高い**:`git fetch origin <指定ブランチ名>`が
  `couldn't find remote ref`で失敗した場合、`git ls-remote origin`で
  実在するブランチ一覧を確認すること。担当ブランチが本当に無ければ、
  最新の`main`から同じ名前で再作成し、そのブランチで新しいPRを作る
  (マージ済みの古いブランチを再利用しようとしない)。
- **ヘッドレステストは`image/`・`sound/`をシンボリックリンクした
  一時ディレクトリで行うと、セーブファイルを汚さずに済む**:
  モジュール冒頭で`pygame.image.load("image/...")`のように相対パスで
  画像を読み込んでいるため、セーブファイル分離のために作業ディレクトリを
  一時ディレクトリに`chdir`すると`FileNotFoundError`になる。
  `os.symlink(repo内のimage, tmpdir/image)`・同様に`sound/`もリンクして
  から`chdir`すれば、大きなアセットフォルダをコピーせずに済み、
  `savefile*.json`等のテスト用セーブデータもリポジトリ外の一時領域に
  閉じ込められる。
- **新しいフロア特性のアイデアが尽きてきたら、既存の`modifier_*()`関数の
  「逆」を考えると見つけやすい**:今回追加したTorchlit Floor(視界+2)は、
  既存のFoggy Floor(視界-2)を実装している`modifier_vision_delta()`に
  分岐を1つ足すだけで実装できた。新しい`modifier_*()`関数をゼロから
  設計するより、既存の関数が持つパラメータの符号を反転させるだけで
  「対になる特性」を安全に追加できる場合が多い。
- **新しい敵モンスターを追加する場合、画像スロットが埋まっていても
  「既存の絵に色を掛け合わせる」手で新モンスターを成立させられる**:
  通常敵の画像スロット(`image/enemy0.png`〜`enemy29.png`+個別ファイル名)は
  rev163時点ですべて使用済みで空きが無い。Hugging Face MCP経由の画像生成
  自体は成功する(`gr1_z_image_turbo_generate`等でプレビューは見える)が、
  生成画像を配信しているhf.spaceホストへの接続はこのセッションの
  ネットワークポリシーで403拒否され、ローカルに保存する手段が無かった
  (`curl`/`WebFetch`いずれも同じホストで失敗。ポリシー拒否はリトライ・
  回避せず、報告のうえ別の実装に切り替えるのが正しい対応)。この
  ケースでは、Elite個体(`ELITE_TINT`)やドッペルゲンガー
  (`DOPPELGANGER_TINT`)と同じ`tint_surface()`による色調変更を新モンスター
  にも使い、既存の敵画像を色違いとして流用することで、新規アセットの
  取得に失敗しても新モンスター追加そのものは諦めずに実装できた
  (rev163の「Voidforged Golem」= 紫色に染めたIron Golem)。将来また
  同様に画像取得がブロックされた場合も、まずこの色替え手法が使えないか
  検討するとよい。
- 自動開発を行っている実行環境には `gh` CLI が入っておらず、GitHub操作
  (PR作成・確認・マージ等)は GitHub MCP サーバー経由のツールで行っている。
  もし別環境で `gh` コマンドが使えない場合は、PATH の通った `gh` の
  フルパスを確認するか、GitHub MCP/API 経由の代替手段に切り替えること。
- テスト用の実行環境には `pygame` がプリインストールされていないことがある。
  `py_compile` は問題なく通っても、ヘッドレス起動テスト
  (`SDL_VIDEODRIVER=dummy`)の前に `pip install pygame` が必要になる場合がある。
- ヘッドレス動作確認で `runpy.run_path()` を使うと戻り値の名前空間が
  実際にロードされたモジュールの `__globals__` とは別物(コピー)になり、
  グローバル変数を書き換えても関数側の挙動に反映されない。フロア特性など
  グローバル状態に依存するロジックを対話的にテストする場合は
  `importlib.util.spec_from_file_location` + `module_from_spec` +
  `exec_module` で実モジュールとしてロードすること。
- 効果音配列 `se`(`pygame.mixer.Sound` のリスト)は `main()` 関数内で
  ローカル変数として作られており、`global se` 宣言もされていないため、
  `main()` の外で定義された関数(`move_player()` など)から直接
  `se[n].play()` を呼ぶと `NameError` になる(実際にこのPRで一度踏んだ)。
  `main()` の外から効果音を鳴らしたい場合は、既存の
  `achievement_sound_pending` と同じ「フラグを立てて `main()` の
  メインループ側で再生する」パターンに倣うこと。
- `importlib` で実モジュールとしてロードする際、モジュール冒頭で
  `pygame.image.load(...).convert_alpha()` を呼んでいる箇所があるため、
  `pygame.init()` と `pygame.display.set_mode((880, 720))` を
  **`exec_module()` より前に**実行しておかないと
  `pygame.error: video system not initialized` で読み込みに失敗する。
- `main()` は `while True` の無限ループなので、ヘッドレスで動作確認する際は
  `pygame.event.get` を数十フレーム分だけ空リストを返し、その後
  `pygame.QUIT` イベントを1件返すダミー関数に差し替えると、
  `sys.exit()` 経由でクリーンに抜けられる(戻り値は`SystemExit`として
  捕捉する)。
- **新しいrevファイルを作る前に、他にまだマージされていないPRが同じ
  rev番号や似たアイデアを予約していないか確認すること**:このリポジトリは
  1時間ごとに複数の自動実行が並行して走ることがあり、`main`にマージ済みの
  最新rev番号だけを見て次の番号を決めると、別のまだオープンなPRが同じ
  ファイル名(例:`dungeon_rev144.py`)や同じ方向性の特性・実績(例:
  遭遇率を上げるフロア特性)をすでに提案していて、後からadd/addの
  コンフリクトや内容の重複が起きることがある。作業を始める前に
  GitHub MCPの`list_pull_requests`(`state: "all"`)でオープン中のPRの
  タイトル・提案ファイル名を確認し、被りそうならアイデアを変える
  (番号自体は慣例どおり「mainの最新+1」のままでよいが、機能内容は
  オープンPRと重複しないものを選ぶ)。
- このPRのテスト中、`draw_crit_flash()` の透明度計算が
  `crit_flash_timer > CRIT_FLASH_FRAMES` の場合(コンボフィニッシャー
  `+4`・自己ベストコンボ更新`+2`)に255を超えてしまい、
  `pygame.Surface.fill()` が `ValueError: invalid color argument` で
  クラッシュする不具合を発見した(rev133時点から存在していた既存バグ)。
  0〜255の範囲を超えうるアルファ値/色成分は、ダメージポップアップの
  実装と同様に必ず `max(0, min(255, ...))` でクランプすること。
  「起動するか」だけでなく、実際にトリガー値を再現して関数を呼ぶ
  ピンポイントなテストをしないと見つからない類のバグなので、
  新しい演出を追加・変更したときは可能な範囲で実際の値を使った
  再現テストも行うとよい。
